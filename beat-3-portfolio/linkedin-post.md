I built an AI-assisted workflow to help developers find open-source issues that are worth contributing to. I created a custom evaluation rubric and search process to assess whether an issue is active, unclaimed, manageable, and aligned with a contributor’s skills.

The workflow scanned 180 unique issues and narrowed them down using evidence from project activity, contribution guidelines, issue status, and the work requested. One early result exposed an important gap: a project’s main programming language does not always match the task itself. I refined the evaluation to focus more closely on the actual work involved, rather than relying on repository-level information alone.

The project ended with a repeatable issue-discovery process and a selected candidate issue in the Rikaikun project. I submitted a pull request as part of this work. The experience reinforced that useful AI tools need clear criteria, evidence-based checks, and human judgment—not just automation. It also helped me turn an ambiguous search process into a workflow I can evaluate and improve.
